# Milestone 1 API

All paths are same-origin. JSON property names are camelCase. GUID path parameters identify resources; authenticated membership is always checked separately. Error responses use Problem Details where generated by application code; bare 401/403 responses can come from cookie authentication. No redirects to HTML login pages.

## Session

- `GET /api/auth/csrf`: sets the antiforgery cookie and returns `{ "token": "..." }`. Fetch a fresh token after any sign-in/sign-out.
- `POST /api/auth/login`: `{ "email": "chef@dinder.local", "password": "..." }`; returns 204 on success, 401 for invalid/locked credentials, 400 for malformed input or missing antiforgery token, 429 for throttling.
- `GET /api/auth/me`: authenticated email and an array of household IDs, names, and household-specific `Chef`/`Member` roles.
- `POST /api/auth/logout`: invalidates the browser session cookie; returns 204.

Every mutating request, including login, must send the antiforgery cookie and `X-CSRF-TOKEN` header. Session cookies are HttpOnly and SameSite=Strict; Secure is mandatory outside Development/Testing. No token is stored in localStorage.

## Household

- `GET /api/households/{householdId}/kitchen`: household name, caller role, active round or null, sample recipe details, and only the caller's active-round votes.
- `POST /api/households/{householdId}/rounds`: Chef only. Returns the new round's ID, UTC start time, and target Yes count. Returns 409 if a round is already active.
- `PUT /api/households/{householdId}/rounds/{roundId}/votes/{recipeId}`: `{ "choice": "Yes" }`, `"No"`, or `"Skip"`. Missing, unknown, null, and numeric choices are invalid. The user ID comes from the session. Creates or updates that caller's single vote for the recipe in the round and returns recipe ID/choice. Closed rounds return 409; foreign or missing resources return 404.

The PUT operation replaces the current preference; sequential repeats do not insert more rows. Concurrent first writes may return 409 and should be retried after refresh. Concurrent updates are last-write-wins. The API does not expose other members' votes in Milestone 1.

## Health

- `GET /health/live`: 200 if the process can serve requests.
- `GET /health/ready`: 200 if PostgreSQL accepts a connection, otherwise 503. This is connectivity readiness, not a full schema audit.

Static API documentation is sufficient for this small private contract. There is no OpenAPI UI/runtime dependency or formal API version prefix yet.
